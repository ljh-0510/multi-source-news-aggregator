# 多元信息台 · Multi-Source News Aggregator

> 拒绝信息闭塞：把 27 个不同立场的媒体聚合成一张网，让「谁在说同一件事、说法有何不同」变得可见。
>
> **零第三方依赖**，仅使用 Node.js 内置模块（http / https / zlib / crypto / fs）。

## 一、这个项目在解决什么

信息茧房的技术本质不是「来源少」，而是「**看到的叙述方式单一**」。多数聚合器只做「堆在一起」，把 20 个源的标题倒进一个列表 —— 这不叫多元，这叫更大的回声室。

本项目的做法：

1. **立场分布熵**替代源数量作为多元度指标 —— 源多但立场同质，分数照样低
2. **茧房预警** —— 实时检测当前视野是否正在收敛，并给出「去看另一面」的一键入口
3. **议题对照视图** —— 同一议题下不同立场的报道并排呈现，自动标注「事实分歧」与「视角差异」

## 五、几个关键实现

### 5.1 话题聚类：三条防「过度合并」的约束

聚类最容易出的问题是把不相关的新闻粘成一个雪球。三重约束：

```js
// ① 只在跨来源的条目对之间累计共享词 —— 同一家媒体的系列报道不会自己抱团
if (items[list[a]].source === items[list[b]].source) continue;

// ② 相似度门槛：共享词数 / 较短指纹长度 >= 0.34
var sim = shared / shorter;
if (sim < 0.34) return;

// ③ 簇大小上限 —— 弱连接不会把两个大簇粘成一个雪球
if (sz[ra] + sz[rb] > CLUSTER_MAX) return;
```

### 5.2 关键词指纹：区分「实词」与「泛词」

停用词分三层：虚词、媒体套话、高频动词。第三层最关键 ——「watch live 直播」与「Apple Watch 新闻」若不清掉高频动词会被误判成同一话题。

进一步用**全局文档频率（DF）**过滤：只保留出现 ≥2 次、且出现率 ≤7% 的词作为指纹词。这样「苹果」「发布」这类泛词被排除，「折叠屏」「关税」这类才是有效指纹。

### 5.3 多元度：测立场分布而非源数量

```js
// 立场分布的归一化香农熵：分布越均匀，值越接近 100
var ps = leanKeys.map(function(k){ return byLean[k] / n; });
var H = -ps.reduce(function(a,p){ return a + (p > 0 ? p * Math.log(p) : 0); }, 0);
var score = leanKeys.length > 1 ? Math.round(H / Math.log(leanKeys.length) * 100) : 0;
```

**为什么不用源数量**：实测数据下，27 个源里 13 个属科技商业类（占条目 43.7%），源数熵给出 97 分的虚高分数；而立场熵给出 82 分。用户若只勾选那 13 个源，源数熵仍是 96 分（错误地显示"很均衡"），立场熵直接归零（正确地显示"单一视角"）。

**指标必须测茧房真正发生的地方。**

### 5.4 茧房预警

```js
if (n >= 10 && leanTop > 0.55 && leanCount >= 2) { /* 触发预警 */ }
```

三重条件缺一不可：样本量不足时统计不可靠；只有一类立场时不叫茧房（是单一信源）；阈值 55% 避免轻微偏向就报警。

预警卡片给出**对立面一键入口**（`COUNTER` 映射表），点击直接切换到另一立场的筛选结果。

### 5.5 议题对照：差异类型判定

同一议题下各立场报道并排后，还需要告诉用户「这些差异是事实层面的还是视角层面的」：

- **事实分歧** —— 两个以上视角都给出了带数字的断言（`\d+%` / 亿 / 万 / 倍 / 人），需核对原始出处
- **视角差异** —— 关注点不同，事实部分并不冲突

这是从「聚合」走向「对比」的关键一步 —— 用户不必自己从一堆条目里找出谁和谁在讲同一件事。

### 5.6 实时推送：SSE 而非轮询

服务端在内容真正变化时才推 `update` 事件：

```js
const changed = added > 0;          // 只有确实多了新条目才算变化
if (changed) {
  state.generation++;                // 版本号自增
  broadcast('update', { generation, added, total, at });
}
```

前端用 `generation` 比对，版本未变不重渲染。同时 `retry: 3000` 让浏览器断线自动重连，25 秒心跳防止代理掐断闲置连接。

### 5.7 分级调度与失败退避

```js
const HOT_MS  = 3 * 60 * 1000;   // 活跃源（科技/商业/中文）3 分钟
const COLD_MS = 15 * 60 * 1000;  // 其余源 15 分钟
function backoffMs(n) { return Math.min(FAIL_BACKOFF_MAX, Math.pow(2, Math.min(n, 5)) * 60 * 1000); }
```

抓取失败的源按 2ⁿ 分钟退避（上限 30 分钟），一个挂掉的源不会每轮都拖慢整体刷新。

## 六、已知边界

- **立场标签是人工配置的**，不是从内容推断的。同一媒体的不同报道可能持不同立场，当前实现按源统一标注 —— 这是刻意的简化，也是一个待改进点
- **源可达性受网络环境限制**。实测 35 个候选源中，Guardian / BBC 中文 / VOA 中文 / RFI / 端传媒 / Hacker News / 虎嗅均连接超时；国内可达的替代源里缺少立场对立面。这是当前多元度提升受限的主因
- 议题对照的「事实分歧」判定基于数字型断言的**存在性**，不做数值大小比较（判断「3%」与「5%」是否矛盾需要领域知识）
- 同步抓取模型，未做请求去重与连接池
- 内存态存储，进程重启即丢失
- 单机部署，未考虑多实例下 SSE 连接的负载分发

## 七、可延伸方向

1. **立场标签内容化** —— 用关键词规则从标题/摘要推断叙述特征（强调冲突 / 强调和解 / 强调数据 / 强调个案），替代人工标签
2. **数值冲突检测** —— 抽取断言中的数字与单位，识别同议题下的矛盾数值
3. **本地缓存层** —— SQLite 存历史条目，支持时间跨度检索
4. **订阅推送** —— 用户订阅某议题，变化时主动通知
5. **容器化部署** —— Dockerfile + compose，当前零依赖设计已为容器化预留
